Personal setup guide

Your Gmail.
Your own reader.

Create your own private reader for multiple newsletters on any topic. Connect one Gmail account, read all your labelled publications in one feed, and filter by newsletter. This guide is for one person's reader.

Before you start: you need a GitHub account, a Google account, and access to Codex with the Sites plugin. The current server depends on Sites authentication. A GitHub Pages upload alone cannot run the reader.

1. Create your own reader.

Fork the repository into your GitHub account and open your fork in Codex. Enable the Sites plugin in your environment. If you do not have access to it, you can still try the sample locally; deploying on another host needs authentication work first.

Ask Codex to prepare a new installation using the prompt below. It covers the hosting changes needed for your copy.

Show the setup prompt for Codex 
Set up this repository as my own private AI Signal reader using Sites.

Create a NEW Site in my account. Do not reuse the author's project_id, Google client, or deployed URLs. Keep the DB binding and the Sites authentication integration.

Publish my fork's docs/ directory with GitHub Pages. Update its app URLs, repository links, privacy contact, screenshots and public icon URLs for my copy. Replace the original deployment's OAuth/origin defaults with my configuration.

Prepare GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, APP_ENCRYPTION_KEY and APP_ORIGIN as server runtime settings. Store secrets only in protected hosting settings, never in Git or VITE_ variables. Give me my exact app origin, public page URLs and Google callback URL so I can complete Google Cloud setup and consent myself.

Your source fork can remain public. Set the reader's audience to private in Sites and keep credentials in protected hosting settings. Publish the information/privacy pages separately. In GitHub, your fork's Settings → Pages can publish from main → /docs. Update those pages for your own installation before using them in Google Cloud.

Your new app origin is the address of your reader, with no path. The examples below use https://your-reader.example.com; replace it with your actual URL.

2. Configure your Google account.

Open Google Cloud Console, create your own project, and enable Gmail API for that project.

Google Auth Platform

  1. Branding: enter your app name, support email and developer contact email. Use your own public information page and privacy notice for the website links. Add their domains and your reader's domain under Authorised domains, without https:// or paths.
  2. Audience: choose External for a personal Google account. Add your own Gmail address as a test user while configuring the app.
  3. Data access: add only https://www.googleapis.com/auth/gmail.modify.
  4. Clients: create an OAuth client with type Web application, using the values below.
Google fieldValue for your installation
Authorised JavaScript originshttps://your-reader.example.com
Authorised redirect URIshttps://your-reader.example.com/api/auth/google/callback
Application home pageYour fork's public information page
Application privacy policy linkYour fork's public privacy page

The callback belongs to the reader, not to GitHub Pages. Save the client ID and client secret securely. Keep a downloaded OAuth JSON file outside your repository.

Then go to Audience → Publish app and confirm the status is In production. Google's Testing status expires Gmail authorizations after seven days. Publishing the OAuth configuration does not make your private reader or mailbox public.

Google documents a verification exception for personal use; an unverified-app warning and user cap may remain. Only authorize the app you created and the Gmail permission you expect. Turning this into a service for unrelated users requires a separate review of Google's requirements.

About the permission: Google does not offer a label-specific OAuth grant. Read-status sync needs gmail.modify, a broad permission that includes reading, composing, sending and moving mail to Trash. AI Signal’s server only reads _AI_SIGNAL messages and changes their UNREAD flag. It exposes no send, trash or delete routes.

3. Save your connection settings.

Configure these values in your own Site's server environment. Codex can help using protected hosting settings; do not paste secret values into source files or public issues.

SettingWhat to use
APP_ORIGINYour exact reader origin, without a path or trailing slash
GOOGLE_CLIENT_IDYour web OAuth client ID; this is public
GOOGLE_CLIENT_SECRETYour web OAuth client secret; store as a secret
APP_ENCRYPTION_KEYA random 32-byte base64/base64url key; store as a secret and keep it stable

Redeploy after saving these settings. Open your private reader, complete its Sites sign-in, and tap Connect Gmail. Complete Google's consent yourself. The configured server stores an encrypted connection and renews short-lived access automatically.

If you connected while Google was still in Testing, use Sign out in AI Signal and reconnect once after switching to In production. Google can still require reconnection if access is revoked or a grant expires for another reason.

4. Add newsletters and start reading.

  1. In Gmail, create the label _AI_SIGNAL, including the leading underscore. This name is fixed, even if your newsletters cover other topics.
  2. Apply it to editions from one or several newsletters. They appear together in the feed, with a filter for each detected publication. To label future editions, create a Gmail filter for each sender or newsletter.
  3. Refresh AI Signal. Unread editions have bold titles. Tap a title or preview to open it and mark it read in Gmail. Use Aa → Mark as unread to make it unread in Gmail again. Aa appears on the feed and inside the reader. Text size, default view and image preferences stay saved when you close and reopen on this device. Swipe left for the next edition or right for the previous one; the arrows work too. Navigation stops at each end.
  4. On iPhone, open your reader in Chrome or Safari, then use Share → Add to Home Screen. In Safari, enable Open as Web App if offered. No Apple Developer membership is needed.
  5. Close and reopen the reader to check that the Gmail connection restores.

Newsletter filters appear automatically as publications are detected. The newest 30 editions are cached on this device, separately for each Gmail account. They appear immediately while the app checks Gmail for changes in the background. Unchanged articles are reused. Older editions load when you scroll further. Read status comes from Gmail; reading preferences stay on this device. A Home Screen app and your browser can have separate app sign-in sessions, but the same Sites identity restores the saved Gmail connection.

After upgrading from read-only access, add gmail.modify under Google Cloud → Google Auth Platform → Data access, then use the reader’s Reconnect Gmail prompt once. The app keeps working with an older connection, but cannot mark editions read until you grant the new permission. A small Gmail change check runs whenever you open or return to the app and every ten minutes while visible. Repeated focus events are grouped; unchanged mailbox data skips edition fetches. Manual refresh always checks edition data. There is no polling while hidden or closed.

Common fixes

Google says the redirect URI does not match.

Copy the full callback from your own deployment into the web client's Authorised redirect URIs. Check the scheme, hostname, port and /api/auth/google/callback path exactly. Use your reader URL, not your public docs URL.

Publish app is disabled.

Save Branding with the app name, contact emails, homepage, privacy-policy URL and required authorised domains. The website links must describe your copy and its data handling. Review Google's Branding guidance, then return to Audience.

The feed is empty.

Check the connected Gmail account and the exact label name _AI_SIGNAL. Apply it to individual newsletter messages, then refresh. AI Signal does not fall back to your inbox.

I lose the Gmail connection after closing.

Confirm the server settings, D1 binding and deployment are configured. A browser-only fallback does not retain login. Check that Google is In production, then reconnect once. Keep APP_ENCRYPTION_KEY stable.

The Home Screen icon shows a letter.

Load the reader fully in your browser, remove the older Home Screen shortcut, and add it again. Your copy's public PNG icon URLs must be reachable without a sign-in cookie.

I need local development or another hosting provider.

See the development guide for local environment files, migrations, architecture and hosting boundaries. The current server trusts Sites identity; another host needs its own trusted authentication implementation.
